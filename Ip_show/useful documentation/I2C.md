# Inter-Integrated Circuit ($\text{I}^2\text{C}$) Protocol Guide

This document provides a complete technical explanation of the **$\text{I}^2\text{C}$ (Inter-Integrated Circuit)** synchronous, multi-master/multi-slave serial communication bus used in embedded electronics and robotics (such as the Raspberry Pi, ADS1115 ADC, and SSD1327 OLED display).

---

## 1. Core Philosophy & Physical Layer

$\text{I}^2\text{C}$ is a synchronous, bidirectional, 2-wire serial bus invented by Philips (now NXP). It enables a controller (Master) to communicate with multiple integrated circuits (Slaves) using only **two signal lines**:

1. **`SDA` (Serial Data):** Transmits data bits bidirectionally between master and slave devices.
2. **`SCL` (Serial Clock):** Carries the clock pulse generated by the master to synchronize bit sampling.


### Open-Drain & Pull-Up Resistors
* Both `SDA` and `SCL` lines use **open-drain** (or open-collector) drivers. 
* Devices can only actively pull the line **LOW** ($0\text{ V}$ / Ground). 
* External **pull-up resistors** ($R_{\text{pullup}}$) pull the line back **HIGH** ($V_{\text{DD}}$) when no device is driving it LOW.
* This architecture prevents short circuits if two devices attempt to drive the bus simultaneously (bus contention).

---

## 2. Bus Bus Signals & Timing Conditions

Data on the `SDA` line must remain stable while `SCL` is HIGH. Changes on `SDA` while `SCL` is HIGH are strictly reserved for special bus conditions: **START** and **STOP**.

```
       SCL  ──────┐        ┌──────┐        ┌──────
                  └────────┘      └────────┘
       SDA  ────────┐                  ┌──────────
                    └──────────────────┘
            |  START Condition  |   STOP Condition  |
```

1. **START Condition (`S`):**
   * Transmitted by the Master to initiate a transaction (=complete sequence of data exchange).
   * `SDA` transitions from **HIGH to LOW** while `SCL` remains **HIGH**.
2. **STOP Condition (`P`):**
   * Transmitted by the Master to terminate a transaction and release the bus.
   * `SDA` transitions from **LOW to HIGH** while `SCL` remains **HIGH**.
3. **Data Validity:**
   * Bits are sampled on the **rising edge** or during the **HIGH level** of `SCL`.
   * `SDA` is only permitted to change state when `SCL` is **LOW**.

## 3. Detailed Frame Architecture (Bit-by-Bit Breakdown)

An $\text{I}^2\text{C}$ transaction consists of 8-bit sequences (bytes), each followed by a 1-bit Acknowledge/No-Acknowledge ($\text{ACK}/\text{NACK}$) signal from the receiver.

```text
Bit:   | S |  A6 A5 A4 A3 A2 A1 A0 | R/W |  A  |  B7 B6 B5 B4 B3 B2 B1 B0  |  A  |  D7 D6 D5 D4 D3 D2 D1 D0  |  A  | P |
       |---|-----------------------|-----|-----|---------------------------|-----|---------------------------|-----|---|
Frame: | S | 7-bit Device Address  | 0/1 | ACK |  Register / Control Byte  | ACK |         Data Byte         | ACK | P |

```

### Frame Component Descriptions

1. **START Bit (`S`, 1 bit):**
* The Master pulls `SDA` **LOW** while `SCL` remains **HIGH** to signal the beginning of a communication frame.


2. **Device (Slave) Address (`A6..A0`, 7 bits):**
* **Function:** A unique 7-bit hardware address used to select a specific chip on the shared physical bus (e.g., `0x48` for the ADS1115 ADC, `0x3C` for the SSD1327 OLED).
* **Determination:** The upper bits are hardcoded into silicon by the **chip manufacturer**, while the lower bits are set by the **circuit board designer** via physical pin strapping (e.g., wiring the `ADDR` or `DC` pin to `GND` or `VDD`).


3. **Read/Write Bit ($\text{R/}\overline{\text{W}}$, 1 bit):**
* `0` ($\text{Write}$): Master intends to send data or register pointers to the slave.
* `1` ($\text{Read}$): Master requests to read data from the slave.


4. **Acknowledge Bit ($\text{ACK}/\text{NACK}$, 1 bit):**
* After every 8 bits (1 byte) sent, the receiving device pulls `SDA` **LOW** during the 9th clock pulse to signal an **$\text{ACK}$** (Acknowledge), confirming the byte was successfully received.
* If `SDA` remains **HIGH**, it indicates a **$\text{NACK}$** (No Acknowledge), meaning the target device is absent, busy, or unasserted.


5. **Internal Register / Control Byte (`B7..B0`, 8 bits):**
* **Function:** Specifies the internal memory pointer or command mode within the target device (e.g., Config Register `0x01` on the ADS1115, Control Byte `0x00` for commands on the SSD1327).
* **Addressing Hierarchy:** Every device on the bus has its own **Device Address**, and within each device, memory slots/features have their own **Register Addresses**.
* **Determination:** Register addresses are **100% fixed by the chip manufacturer** in the silicon logic and defined in the datasheet.


6. **Data Payload (`D7..D0`, 8 bits per byte):**
* The actual command parameters, digitized sensor outputs, or graphic pixel data being transferred.


7. **STOP Bit (`P`, 1 bit):**
* The Master transitions `SDA` from **LOW** to **HIGH** while `SCL` is **HIGH**, returning the bus to the **IDLE** state.

## 4. Master Write vs. Master Read Sequences

### Master Write Sequence (Sending Commands/Data)

To write configuration parameters or display content:

$$\text{Master} \xrightarrow{\text{START}} \text{Slave Addr + W (0)} \xrightarrow{\text{ACK}} \text{Register Pointer} \xrightarrow{\text{ACK}} \text{Data Byte 1} \xrightarrow{\text{ACK}} \dots \xrightarrow{\text{STOP}}$$

```
Master:  | S | Address + 0 |     | Register/Cmd |     | Data Byte 1 |     | P |
Slave:   |   |             | ACK |              | ACK |             | ACK |   |
```

### Master Read Sequence (Retrieving Sensor Data)

Reading data requires a **two-step sequence**: first setting the register pointer via a write, then re-issuing a START (or Repeated START) with the Read bit set.

1. **Step 1:** Write to set the Internal Pointer:
   $$\text{Master} \xrightarrow{\text{START}} \text{Slave Addr + W (0)} \xrightarrow{\text{ACK}} \text{Target Register Pointer} \xrightarrow{\text{ACK}}$$

2. **Step 2:** Read from the selected register:
   $$\text{Master} \xrightarrow{\text{REPEATED START}} \text{Slave Addr + R (1)} \xrightarrow{\text{ACK}} \text{Read Byte 1 (from Slave)} \xrightarrow{\text{Master ACK}} \text{Read Byte 2} \xrightarrow{\text{Master NACK}} \xrightarrow{\text{STOP}}$$

## 6. Summary of Protocol Advantages & Constraints

### Advantages
* **Minimal Pin Count:** Requires only 2 GPIO pins on the microcontroller regardless of how many devices are attached.
* **Hardware Addressing:** Built-in 7-bit addressing eliminates the need for individual chip-select lines (unlike SPI).
* **Acknowledgment Mechanism:** Every byte transmitted is confirmed by an ACK pulse.

### Constraints
* **Half-Duplex:** Cannot transmit and receive data simultaneously.
* **Speed Limits:** Standard mode is $100\text{ kbit/s}$, Fast Mode is $400\text{ kbit/s}$, and High-Speed mode is $3.4\text{ Mbit/s}$.
* **Bus Capacitance:** Long wiring runs increase line capacitance, slowing signal rise times and limiting maximum distance.
